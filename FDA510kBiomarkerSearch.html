Biomarkers
LDT data sources:
  • Terms are matched against device name and 510(k) summary text (openFDA has no dedicated "biomarker" field).
  • Greek letters (α, β, …) are automatically spelled out (alpha, beta, …).
  • If an exact phrase finds nothing, the search automatically widens — first dropping word order, then the Ig-class suffix — and flags the result as Broad match / Antigen-only match so you know it's less precise.
  • "Anti-" is never dropped when the term has it — it distinguishes an antibody test from the antigen itself, so a real match must still contain it, though not necessarily the literal word "anti" ("antibody", "antibodies", "autoantibody", "autoantibodies", and "AB" all count too), and not necessarily in the same field as the antigen name — FDA splits one device's info across several fields, and it's common for the antigen abbreviation to appear in one and the antibody wording in another.
  • If an exact/broad/antigen-only search finds nothing, a UMLS API key (set in Settings) can look up the term's spelled-out medical name automatically instead of returning nothing — flagged as UMLS-resolved match since that name hasn't been manually verified.
  • Checks up to 4 sources at once — pick which ones in the "LDT data sources" row above. Only NY State is an actual regulatory LDT approval record; ARUP, LabCorp, and Quest just mean the term appears in that lab's own commercial test catalog — real signal, but not a regulatory fact.
  • NY State and Quest each need a proxy Worker URL configured in Settings (gear icon) — both sites block direct requests from this tool. ARUP and LabCorp need no setup at all.
  • Each source's own search casts a wide net, so this tool then requires every one of the term's significant words to actually appear in a record before counting it as a real match (not just any one of them) — a multi-word term like "Beta-2 Glycoprotein I Domain 1" won't match a record that only happens to mention "Domain" or "Glycoprotein" on its own.
